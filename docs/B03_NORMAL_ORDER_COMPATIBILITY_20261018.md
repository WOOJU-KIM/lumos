# B-03 전후 정상 거래 경로 비교

2026-10-18 KST. 사용자 요청: 지난주 정상 거래 이력과 수정 전후 경로를 확인하되 다음 주 실거래 계획을 임의 변경하지 않는다.

## 결론

확인 범위에서 B-03 변경 때문에 정상 매수·매도 경로가 깨졌거나, 현재 평탄 계좌의 신규 진입이 추가로 차단되는 증거는 발견하지 못했다. 이번 확인은 주문을 보내거나 Live Runner를 가동한 실전 검증이 아니다.

이전 READY 점검에서 발견한 계좌 결합 검사 부재는 **B-03 이전부터 동일한 코드에 존재**한다. `core/circuit_breaker.py` 전체 및 broker의 `send_order`, `_send_tr_request`는 저장된 수정 전 소스와 AST가 동일하다. 이 문제를 근거로 B-03 이후 거래 불가를 예측해서는 안 된다. 발견한 검증 결함 자체가 해소된 것은 아니다.

## 실제 기록

읽기 전용 SQLite의 앱 완료 거래 기록은 20행이며 모두 REAL/SOXL이다. 기록의 KST 시각을 뉴욕으로 변환한 세션별 기록 수는 10/13 2행, 10/14 1행, 10/15 9행, 10/16 8행이다. 이는 앱 기록 집계로 독립적인 증권사 정산 거래 수와 동일시하지 않는다.

별도 allowlist 진단에서 실전 인증 및 조회만 사용했다. 이번 작업의 네트워크 진단은 3회이며 인증 3회와 조회 18회다. 대상은 잔고·미체결·10/16 체결 및 10/16~17 주문내역이다. 토큰·계좌번호·주문번호·원문 응답은 출력/저장하지 않았다. 첫 비교에서는 `slby_tp_nm` 별칭 누락으로 후보가 0개였고, 진단 스크립트만 수정해 원래 문자열 필드까지 수용했다. 초기 결과는 별도 보존하고 증거로 사용하지 않는다.

## 수정 전후 재현

실제 브로커 조회 행을 메모리에 유지한 채, 보존된 B-03 이전 함수와 현재 함수를 AST로 추출해 동일 입력으로 호출했다. Broker 생성자나 Runner 가동 없이 순수 비교했다. 주문 식별자는 내부 대조에만 사용했다.

| 비교 | 수정 전 | 현재 |
|---|---:|---:|
| 조회된 주문 식별자 | 22 | 22 |
| FILLED | 18 | 18 |
| CANCELED_ZERO_FILL | 2 | 2 |
| UNKNOWN | 2 | 2 |
| 평탄 계좌 진입 전 원장 검사 | 허용 | 허용 |

22개 식별자별 status, ord_qty, filled_qty, cancelled_qty, remaining_qty가 모두 일치했다. UNKNOWN 2개는 양쪽 모두에 남으며 이번 수정으로 새로 생긴 차단이 아니다. 주문 식별자에는 취소 등 별도 요청이 포함될 수 있으므로 22개를 원주문 22개나 거래 22건으로 부르지 않는다. 취소 요청의 세부 상태를 새로 추정하거나 운영 상태에서 지우지 않았다.

또한 네트워크 및 운영 경로 쓰기를 차단한 격리 복사본에서 실제 수정 전후 Runner·Broker 메서드에 같은 모의 계약을 제공했다. WS 체결 통지와 원장 보유량이 일치하는 정상 매수→매도 1사이클은 양쪽 모두 성공했다. 양쪽 주문은 매수 4주 $100.03, 매도 4주 $99.95로 같았고 종료 후 pending BUY와 포지션이 없었다. 이는 합성 계약 REPLAY이며 과거 가격 백테스트나 실제 체결이 아니다. 최초 진단 hook의 키 이름 오류는 진단 스크립트에서 수정 후 재실행했다.

## 실제 달라지는 조건

- WS 체결 통지만으로 완료 처리하지 않고, 최신 원장 잔고로 확인한다. 원장 반영이 지연되면 확인이 늦어질 수 있다.
- 접수된 미확인 BUY를 디스크에 보존한다. 저장 실패·손상·다른 계좌/환경 및 불명확한 전일 주문은 신규 매수를 차단한다.
- 재주문 판단에서 원장 조회 실패·원장 간 수량 모순·필수 수량 누락을 UNKNOWN으로 유지한다.
- 매도 잔고 조회 실패 또는 매도 가능 수량 0일 때 임의로 보유 수량을 재주문하지 않는다.

따라서 정상 경로의 호환성 증거는 확보했으나, 지연·불명확한 원장에서는 이전보다 보수적으로 동작한다. 다음 장에서 원장 응답 지연과 주문 확인 시간은 실제 관측이 필요하다. 모델 판단, 진입 임계값, 틱 기반 청산 기준 및 주문 전송 API는 이번 확인에서 변경하지 않았다.
