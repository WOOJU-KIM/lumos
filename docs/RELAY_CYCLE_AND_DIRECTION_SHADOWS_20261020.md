# 사이클당 연쇄 1회 제한 및 진입 비교 쉐도우 2개

2026-10-20 사용자 지시 반영. 실제 운영 Runner와 쉐도우 프로세스는 이번 작업에서 실행하지 않았다. 다음 Live Runner 실행 시 기존 FOLLOW_LIVE_RUNNER 경로로 함께 시작·종료한다.

## 현재 실전과 신규 쉐도우의 공통 거래 방식

- 포지션·미체결·미해결 주문이 없는 상태에서 새로 완료된 15분봉으로 최초 49% 진입한다. 정규장 첫 진입 판단은 09:45 NY 이후다.
- 최초 포지션의 자기 매수가 대비 -1%에서 반대 종목 49%를 한 번만 매수한다.
- 최초 또는 연쇄 중 한쪽이 먼저 팔려도 추가 매수하지 않는다. 남은 포지션은 기존 청산 규칙으로 관리한다.
- 모두 청산되고 주문 정리가 완료된 뒤 다음 새 15분봉에서만 새 사이클을 시작한다.
- 최초 추적 발동 +1.5%, 연쇄 추적 발동 +1%, 고점 대비 추적 -0.3%, 공통 손절 -2%, 기존 최대 익절·시간 종료·EOD 기준은 유지한다.

과거 코드는 빈 반대 종목을 반복 연쇄 매수할 수 있었다. 이번 변경이 그 반복을 차단한다. 이전 대화에서 이미 차단되어 있다고 설명한 내용은 실제 코드와 달랐다.

## 실전의 제한 저장 및 주문 경로

`RelayBook.begin()`에서 새 사이클의 `chain_operation_id`를 초기화한다. `RelayBook.operation()`이 최초 CHAIN 매수 의도와 예약 ID를 같은 원자적 저장으로 기록한다. 해당 매수의 가격 재발주 등 기존 주문 처리 안에서는 같은 ID를 유지하며, 별도 두 번째 CHAIN 의도는 거절한다.

`RelayLiveRunner._chain_available()`과 매수 실행 함수, 실제 브로커 송신 직전 검사에서 제한을 확인한다. 한쪽의 포지션 파일이 사라지거나 프로세스가 재시작해도 예약은 남는다. 이미 진행 중인 구 형식 사이클에 예약 필드가 없으면 추가 매수는 차단하고 기존 청산만 계속한다. 모두 평탄화된 후 새 사이클부터 정상 초기화된다.

보수적으로 연쇄 매수 의도를 예약한 후 취소·실패해도 그 사이클의 기회를 재사용하지 않는다. 동일 의도 안의 기존 미체결 취소·재발주 처리는 유지한다. 원장 조회·실제 체결 확인·계좌 READY·호가 유효성·수량 제한은 유지했다.

## 신규 쉐도우

| ID | 최초 진입 판단 |
|---|---|
| RELAY_B72_NO_THRESHOLD | GBDT 점수 임계값 제거. 중립이 최댓값이면 대기. 그 외 롱·숏 중 큰 방향 |
| RELAY_B72_DIRECTION_ONLY | 점수 임계값과 중립 진입 차단 제거. 롱·숏 중 큰 방향 |

현재 실전 B72와 SHA가 같은 모델 아티팩트와 동일 피처를 사용하며 재학습하지 않는다. 활성 실전 모델 SHA가 달라지면 구 모델로 비교를 계속하지 않고 명시적 오류를 기록한다. 방향 확률이 정확히 같으면 LONG, 중립 보존형에서 중립이 공동 최댓값이면 대기로 규정했다.

두 신규 쉐도우는 각각 별도 10,000 USD 가상 원장을 사용한다. 49% 한도는 사이클 시작 자금 기준이며, 실제 가상 현금에서 매수 원금을 차감하고 매도 시 반환한다. 실제 주문은 보내지 않는다. 기존 5개 모델의 primary/forced 및 이전 B72 단일 98% 쉐도우는 그대로 두어, sidecar는 총 8개 전략·13개 가상 원장을 로딩한다. 기존 별도 15분 강제 진입 트래커도 변경하지 않았다.

완료 15분봉·교차자산 입력 검증, 설정상 활성 방패, 최신 양 종목 WS 호가를 확인한다. 결정·연쇄 발동 후 다음에 관측된 WS Ask/Bid에서만 가상 체결한다. 의도보다 과거에 관측된 지연 호가로 체결시키지 않는다. 청산 가격은 실제 관측한 다음 Bid이므로 발동선 체결이나 수익은 보장하지 않는다. 왕복 비용은 최소 0.20%를 차감한다.

개별 매매의 역할·진입/청산가·수량·비용·손익과 `VIRTUAL_CYCLE_CLOSED`의 사이클 전체 순손익을 기존 `runs/live_shadow_*/events.jsonl`에 기록한다. 입력은 `decision_inputs.jsonl`, 위험 호가와 청산 의도도 기존 감사 로그에 남는다. `RELAY_DIRECTION_SHADOW_POLICY`는 새 정책과 소스 SHA를 기록한다.

신규 쉐도우는 기존 sidecar와 동일하게 실행 단위의 메모리 가상 원장을 사용한다. 프로세스 강제 종료 후 미청산 가상 포지션을 다음 실행으로 자동 승계하지 않는다. 종료 시 기록되는 미해결 포지션과 실행 구간을 고려해 비교해야 한다. 실전의 사이클 예약은 별도의 영속 원장으로 유지된다.
