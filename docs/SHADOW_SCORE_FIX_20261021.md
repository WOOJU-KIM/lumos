# 15분 강제진입 트래커 점수 저장 수정

기존 러너가 트래커 진입 호출에 점수를 전달하지 않았고, 트래커의 DB worker도 `gbdt_confidence`에 항상 0.0을 넣었다. 과거 호환 wrapper의 confidence 인자도 전달하지 않았다. 때문에 점수와 승률/손익을 비교할 때 원본 모델 로그 복원이 필요했다.

러너는 실제 진입 방향의 `learning_snapshot.displayed_scores` 보정점수(퍼센트), event_id, model SHA를 트래커로 전달한다. 완료된 추론이고 활성 모델 SHA가 같은지 검증한다. 중립 점수나 전체 gating confidence를 방향 점수로 대신 사용하지 않는다. 점수가 없거나 유효하지 않으면 NULL/UNAVAILABLE로 기록하며, 강제진입 자체는 유지한다.

슬롯의 기존 12개 키와 JSONL 형식은 유지한다. 별도 메타데이터를 슬롯 생애에 붙이고, 진입 직후 비동기 worker가 `shadow_entry_signals`에 기록한다. 청산 기록의 shadow_logs에는 같은 signal_id·판단 ID·모델 SHA·점수 출처를 저장한다. 슬롯 재사용 시 메타데이터도 분리한다. 실제 0점과 누락값을 구별한다. 기존 매매 조건·진입 방향·손절·익절·비용 계산은 변경하지 않았다.

운영 DB는 러너/쉐도우 종료를 확인한 상태에서 SQLite backup으로 복사한 뒤 단일 트랜잭션으로 보정했다. DECISION_OUTCOME의 snapshot_id와 DECISION event_id를 연결하고, 같은 뉴욕 날짜에서 진입 시각과 2초 이내의 유일한 판단만 허용했다. 원시 확률의 LONG/SHORT 선택이 실제 종목과 일치해야 한다. 복원 결과는 별도 BACKFILLED 출처와 원본 판단 ID로 추적된다.

- 전체 136건 중 원본으로 복원한 점수 45건. 미국 10/20장 22건은 모두 복원했다.
- 연결 가능한 원본이 없는 89건은 잘못된 0점 대신 NULL/UNAVAILABLE_HISTORICAL로 표시했다. 복구 불가 사유는 backfill.json에 있다.
- 기존 비영점 점수 2건은 보존했다. 실제 거래 가격·수량·손익·청산 사유와 shadow_slots_history는 변경하지 않았다.
- 운영 DB integrity_check=ok, 잘못된 0점 잔존 0건.

격리 복제에서 무결성 9개와 관련 회귀 311개, 총 320개 통과. 신규 15개는 진입 즉시 점수 저장·청산 연결·슬롯 격리·미확인/실제 0점 구분·실제 15분 평가 경로의 전달·복원 검증/백업/롤백을 포함한다. 실제 DB 복사본으로도 45건 복원과 거래 필드 보존을 사전 검증했다. 시험 중 네트워크/외부 쓰기 가드 차단 0건.

config·모델·READY 및 실전 매매 규칙은 변경하지 않았다. 러너와 쉐도우는 사용자 요청대로 종료 상태를 유지했다. 수정 코드는 다음 정상 Live runner 실행부터 사용된다. 증거와 백업은 `research/shadow_score_fix_20261021/`에 저장했다.
