# B72 단일 포지션 → 실전 연쇄 전략 전환

> **후속 수정 완료:** 재검토에서 확인한 복구·외부 수량·완료 봉·계좌 검사를 보완했다. 격리 222개 검증 통과, 현재 실전계좌의 실제 원장 대사로 READY 불일치를 해소했다. 운영 Runner는 미실행이다. 현재 결과는 [후속 수정 기록](RELAY_FIXES_20261020.md)을 따른다. 아래 READY 차단과 213개 QA는 최초 전환 시점의 기록이다.

2026-10-20 사용자 지시에 따라 개발·연결 및 격리 QA 완료. **실행 코드의 기본 선택은 새 전략이며 운영 Runner와 실주문은 실행하지 않았다. 현재 운영 READY 증명의 계좌 불일치로 신규 실전 BUY는 차단된다.**

## 실제 선택과 보존

- 기존 CLI `python core/live_runner.py --real`의 생성 경로를 `create_live_runner()`로 연결했다. config `LIVE_EXECUTION_STRATEGY = OPPOSITE_RELAY_V1`이면 `RelayLiveRunner`가 선택된다. 직접 `KiwoomLiveRunner` 클래스를 생성하는 과거 테스트·샌드박스는 기존 단일 포지션 구현을 사용한다.
- 학습 모델은 새로 만들지 않았다. B72는 새 전략의 최초 15분봉 방향 판단에도 필요하다. 기존 활성 모델 manifest와 PKL SHA는 보존했다.
- 이전 **98% 단일 포지션/+1.5% 트레일링** 전략은 `LEGACY_B72_SINGLE_98`이라는 별도 쉐도우로 보존했다. 동일 B72를 불변 아티팩트 사본으로 복사하고 모델 SHA를 검증한다. 기존 5개 쉐도우의 policy·모델 manifest는 유지했다.
- consumer의 후보 registry에 보존 전략의 primary 원장 하나를 추가했다. 총 6개 전략이며 원래 5개는 primary/forced, 보존 전략은 primary만 사용한다. 시작·종료는 기존 FOLLOW_LIVE_RUNNER와 연결된다.
- `models/active_execution_strategy.json`에 새 실행 전략과 승인된 소스/config SHA를 기록한다. 이 파일의 QA 통과는 실제 계좌 READY 증명과 별개다.

## 실전 매매 기준

| 항목 | 적용 |
|---|---|
| 최초 진입 | 무보유·미체결 없음, 새 완료 15분봉 B72 신호. 현행 64% 기준·Neutral 관망·모델 무결성·config 방패 유지 |
| 최초 주문 예산 | 그룹 시작 직전 주문 가능 USD의 49% |
| 연쇄 주문 예산 | 같은 기준 USD의 49% 상한, 실제 주문 가능 USD에서 그룹 시작 자금의 2%를 뺀 금액도 상한 |
| 연쇄 조건 | 하나만 보유 중이고 그 종목의 자기 매입가 대비 WebSocket Bid 손익이 −1.5% 이하, 반대 종목 슬롯 완전히 비어 있음 |
| 동시 보유 | SOXL/SOXS 각각 1포지션. 매수/매도 미체결 및 미해결 제출도 슬롯 점유 |
| 재진입 | 하나가 원장상 완전히 청산되면 남은 보유의 조건으로 빈 종목 재매수 가능. 새 leg ID와 매입가·고점·시간 앵커 부여 |
| 최초 트레일링 | +1.5% 발동, 고점 대비 −0.3% |
| 모든 연쇄 트레일링 | +1.0% 발동, 고점 대비 −0.3% |
| 초기 손절 | 각자 −2.0% |
| TP/TIME/EOD | config 10%, 각 leg 90분, EOD 전량 청산. 정확한 체결 시각이 없으면 주문 의도 시각을 보수적 TIME 앵커로 보존 |
| 양쪽 모두 종료 | 원장/저널 정리 후 현재 15분 주기 재사용 차단, 다음 새 주기를 기다림 |

매수 직전과 각 재발주 직전에 현재 원장 보유·미체결·발동 보유 존재·예산·세션·호가 신선도를 검증한다. 주문 체결/취소 확인은 기존 매수·매도 추격 헬퍼 및 키움 원장 reducer를 재사용한다. 종목별 영속 경로를 사용해 한 종목의 청산/재매수가 다른 종목 상태를 덮어쓰지 않게 했다.

신규 실전 판단은 `from_ws=True`와 명시적 Bid/Ask가 있는 호가만 사용한다. REST/midpoint를 새 WebSocket 체결 틱으로 간주하지 않는다. 매수 의도/응답만으로 보유를 만들지 않는다. 실제 체결 입고와 평균가를 대조한다. TIME/EOD는 새 호가 없이도 감시하고, 필요한 실전 청산은 시장가 경로를 사용한다.

WebSocket 콜백은 별도 짧은 quote lock으로 고점/저점과 SL/TP 관측을 보존한다. 원장 조회가 진행되는 state lock 뒤에서 WebSocket reader를 기다리게 하지 않는다. 실제 주문은 한 번에 하나씩 직렬화한다.

## 복구와 기록

계좌·모의/실전 결합 해시 아래에 `book.json`, 종목별 포지션 JSON, 종목별 pending BUY 저널, `events.jsonl`을 저장한다. 제출 직전 미해결 표시를 영속 기록하고 응답 주문번호를 추가한다. 재시작 후 세 원장 증거가 `FILLED` 또는 확정 취소 상태이며 실제 보유 수량과 합치될 때만 저널을 해제한다.

응답 주문번호가 없거나 원장 조회가 불명확하면 제출 상태를 지우거나 같은 종목을 재매수하지 않는다. 빈 잔고 응답 하나만으로 기존 포지션을 삭제하지 않는다. 수동 외부 거래로 설명되지 않는 잔고 변화도 신규 진입을 차단한다.

`OPERATION_UPDATED`, `BROKER_LEDGERS_RECONCILED`, `OPERATION_TERMINAL` 이벤트에 cycle/leg/역할/주문 참조/수량을 연결한다. 기존 거래 경험 로그의 risk_settings에도 relay 역할·leg·cycle ID와 실제 역할별 트레일링 발동선을 넣었다. 기존 경험 로그의 청산 가격은 명시적 quote proxy이며 증권사 체결가라고 재표시하지 않는다. 신규 원장 reducer도 수량만 확인한 경우 알려지지 않은 청산가를 만들지 않는다.

## QA 결과

네트워크·격리 밖 쓰기·자식 프로세스를 차단한 최신 소스 복제에서 수행했다.

- `python -B tests/test_system_integrity.py`: **9개 통과**.
- 신규/관련 회귀: **204개 통과**, 합계 **213개**. 초기 49% 진입, 양방향 반대 진입, 재진입 역할, 중복 차단, 완전 무포지션 후 새 봉, 손절/트레일링/TIME/EOD, 호가 부재·REST·stale, 잠깐 발생한 고점/손절 관측, 저장 실패, 부분체결 복구, 모호한 제출·원장, 계좌 불일치 등을 포함한다.
- 실제 KiwoomBroker 코드와 기존 3-원장 reducer를 사용하고 HTTP를 가짜 서버로 가로챈 통합 검증: 최초 BUY → 반대 BUY → 최초 SELL → 빈 종목 CHAIN BUY → 양쪽 EOD SELL. 실제 전송은 없으며 가짜 `ust20000/ust20001` 계약을 검증했다.
- 실제 factory의 `RelayLiveRunner` 생성 및 background/order 없는 startup 통과. 활성 실행 소스 SHA 검증, B72 식별 및 보존 쉐도우 식별 확인.
- 격리 consumer에서 6개 전략 로딩 후 정상 시작·종료, `RUN_STOP valid=true`, 미해결 보유 0. **시장 입력 0건인 시작 검사**이므로 실제 장중 동작 증거와 구분한다.
- 기존 B-03 테스트 1건에 남아 있던 −2.5% 기대값은 이전 사용자 승인 −2% 고정 기준으로 변경했다. 손절을 넓히거나 회귀 조건을 완화하지 않았다.

검증된 소스 SHA, task-local 변경 diff, 로그와 결과: `research/relay_activation_20261020/`.

## 실제 운영 READY 조건

현재 로컬 운영 증명의 `verified_account`와 실제 설정 계좌가 일치하지 않는 것을 원문 노출 없이 다시 확인했다. 실전 API 호출은 하지 않았다. 예전 `order_readiness()`의 자체 digest 검증만으로 이를 승인하지 않도록 새 전략의 모든 BUY에 **현재 broker 계좌·환경 일치 검사**를 추가했다. 해당 검사는 진입 때마다 적용하며 위험을 줄이는 청산 경로를 임의 차단하는 용도로 쓰지 않는다.

운영 READY 파일, 과거 예약 원장 및 검증 증명을 위조·갱신하지 않았다. 따라서 **개발과 코드 선택은 완료했지만 현재 상태의 실전 신규 진입은 차단**된다. 올바른 계좌로 실제 원장 대사와 정당한 증명 갱신을 마쳐야 실전 BUY가 허용된다. 이번 격리 QA 통과를 실제 계좌 가동 READY로 표시하지 않는다.

실전 Runner 시작/재시작, 실제 매수·매도, Telegram 전송은 수행하지 않았다. 이 연쇄 전략의 역사적 수익률 백테스트나 실제 시장 부하 검증을 완료했다고 주장하지 않는다.
