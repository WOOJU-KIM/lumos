# 15분 강제 진입 트래커 유지

후속 사용자 지시에 따라 기존 `ShadowTracker`를 다시 활성화한다. 비교 쉐도우 3개(`ABS72_SINGLE_98`, `ABS72_RELAY_M15`, `ABS72_STOP_REVERSE`)는 변경하지 않는다. 총 관측 전략은 비교 원장 3개와 강제 진입 트래커 1개다.

트래커는 기존처럼 정규장 완료 15분봉마다 롱·숏 중 보정 점수가 높은 방향으로 가상 진입한다. 중립·진입 임계값은 이 트래커의 진입을 차단하지 않는다. 독립 슬롯 10개, 같은 봉 중복 진입 방지, 틱 청산·고정 손절 −2%·기존 트레일링·시간 청산·EOD 규칙을 유지한다. 실전의 사이클 제한은 이 독립 관측 트래커에 적용하지 않는다.

별도 과거 모델을 로드하지 않고 실전 Runner의 현재 `Absolute_72` 판단 결과를 사용한다. 진입 방향의 보정 점수, 판단 ID, 모델 SHA를 진입 DB에 저장하고 청산 기록으로 연결한다. 원본 없는 점수를 임의 생성하지 않는다. 향후 활성 모델 변경도 실전 판단 결과를 따라간다.

격리 복제에서 실제 절대값 모델(SHA `e3e4499a9bf4731dff1d94ff9bffedc45eb9f708f35abf60aa1955b1053fb1ae`)과 실제 과거 봉으로 추론했다. 숏 점수 50.96287242978784%가 실제 15분 평가 경로에서 가상 진입 DB에 저장되고, 불리한 틱으로 청산한 DB에서도 같은 점수·모델 SHA·판단 ID가 유지됨을 확인했다. 테스트에서 실전 주문은 없었다.

관련 회귀 230개 및 시스템 무결성 9개 통과. `config.py`, 활성 모델 파일·매니페스트, 실전 Runner·트래커·연쇄·주문 정책 소스는 그대로다. 실전은 최초 49%/반대 49%, −1% 연쇄를 유지한다. 검증 증빙은 `research/shadow_forced_restore_20261021/`에 보존한다. 운영 Runner는 기동하지 않았으며 다음 정상 시작부터 트래커와 비교 쉐도우가 함께 동작한다.
