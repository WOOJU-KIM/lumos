## 영속 진입 예약 계약

DB 파일 옆 `<db 파일명>.candle_claims/` 아래에 봉 ID의 SHA256 파일명을 사용한다. `os.open(O_CREAT | O_EXCL)`로 진입을 원자적으로 예약한다. 가격·시각·빈 슬롯 확인 이후, 슬롯 활성화 이전에 예약한다. 동일 DB를 사용하는 다른 인스턴스도 동일 봉에는 진입할 수 없다. 봉 ID에 날짜를 포함하므로 날짜별로 구분된다.

SQLite 로그 장애와 예약 저장을 분리했다. 예약 저장 실패는 쉐도우 진입만 거절한다. 실제 판단 함수에서도 이 실패 후 모의 매수 함수까지 정상 진행하는 회귀 검증을 추가했다. 틱별 청산 경로에는 예약 파일 작업이 없다. 진입 예약 시 로컬 파일 작업이 발생하며 운영 디스크 지연은 이번 오프라인 검사로 보증하지 않는다.

이 예약은 체결 기록이나 열린 가상 포지션 복구가 아니다. 예약 직후 프로세스가 종료되면 해당 봉은 보수적으로 소비된다. 전원 장애에 대한 디스크 영속성은 보증하지 않는다. 배포 이전 봉의 진입은 소급 복구하지 않는다. 별도 쉐도우 5개 프로세스 구현과 혼동하지 않는다.
