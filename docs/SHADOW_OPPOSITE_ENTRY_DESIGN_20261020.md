# 실전 연쇄 전략: 손실 −1.5%에서 반대 종목 추가 진입

상태: **개발·기본 실전 경로 선택 및 격리 QA 완료 / 운영 Runner 미실행**. 작성·수정 2026-10-20. 사용자 후속 지시에 따라 이 전략을 실전 실행 경로로 연결하고 이전 B72 단일 포지션 전략을 쉐도우로 보존했다. 현재 계좌와 운영 READY 증명 불일치로 실전 신규 매수는 차단된다. 구현과 검증의 최종 기준은 [실전 전환 기록](OPPOSITE_RELAY_ACTIVATION_20261020.md)이다. 아래 설계 초안의 쉐도우 표현은 전환 이전 배경이며 실제 연결은 5절과 최종 기록을 따른다.

사용자 요구: 본매수의 기존 청산 관리를 계속하면서, 매입가 대비 −1.5%에 닿으면 반대 종목을 매수하고 두 포지션을 독립적으로 청산한다. SOXL 시작이면 SOXS, SOXS 시작이면 SOXL을 추가한다. 초기 손절은 모두 −2%. 트레일링은 포지션 없는 상태의 최초 진입에 +1.5%, 이후 연쇄 진입에 +1% 발동을 적용하며, 모두 고점 대비 −0.3% 추적한다.

## 1. 전략 정의와 예산

전략 ID 제안: `B72_OPPOSITE_RELAY_15_T10_D03_V1`. 학습 모델 하나를 추가하는 것이 아니라, 기존 B72 판단에 다른 포지션 관리 규칙을 적용하는 실행 전략이다.

| 항목 | 설계 |
|---|---|
| 최초 진입 | 현행 B72 모델/72개 피처/보정 점수 기준 및 진입 필터 재현. 현재 config 기준 64% 이상, Neutral 우세·동률 관망 |
| 최초 방향 | LONG이면 SOXL, SHORT이면 SOXS. 신규 백테스트에서 잘 나온 65~70 구간을 자동 적용하지 않는다 |
| 반대 진입 | 실제 가상 체결된 본포지션의 현재 Bid 기준 평가손익이 −1.5% 이하일 때 반대 ETF 추가 매수 |
| 본포지션 처리 | 반대 매수 때문에 강제 매도하지 않는다. 자체 SL/트레일링/TP/TIME/EOD 유지 |
| 반대포지션 처리 | 자신의 체결가·고점·진입시각으로 독립 SL/트레일링/TP/TIME/EOD 적용 |
| 동시 보유 | SOXL 1포지션, SOXS 1포지션까지. 같은 종목의 보유·매수대기·매도대기가 있으면 추가 매수 금지 |
| 연쇄 반대 진입 | 허용. 하나가 완전히 청산되면 남은 종목의 자기 매입가 대비 −1.5% 조건으로 빈 반대 종목을 다시 매수할 수 있음 |
| 재매수 | 그룹 전체 횟수 제한 없음. 빈 종목에 유효한 매수 의도는 한 번에 1개만 존재. 매도 주문 접수만으로 빈 종목이라고 판단하지 않음 |
| 그룹 중 신규 신호 | 하나라도 보유/미체결이면 새 15분봉 본진입 대신 남은 보유의 청산·반대 진입 조건을 관리 |
| 그룹 종료 | 모든 포지션 및 미체결이 해소되었을 때. 다음 새 15분 판단 주기에만 새 그룹 가능 |

사용자 후속 지시로 **한 계좌의 총예산을 본매수 49%, 반대매수 준비금 49%, 현금 여유분 2%**로 분리한다. 반대매수가 발생하지 않으면 해당 49%는 현금으로 유지한다. 신규 트랙의 최초 진입은 +1.5%, 이후 연쇄 진입은 +1%에서 트레일링이 발동하고, 두 경우 모두 고점 대비 −0.3% 추적한다. 각 leg가 최초 진입인지 연쇄 진입인지 체결 시 확정해 저장한다. 기존 트랙의 +1.5% 설정은 변경하지 않는다.

## 2. 진입과 청산 이벤트

가상 체결이 확정된 포지션만 관리한다. 진입 의도만 있고 체결되지 않은 본포지션에서는 반대 매수·손절을 하지 않는다.

본포지션의 발동 손익은 비용 차감 전 `(현재 WebSocket Bid / 실제 가상 매입 Ask) − 1`이다. SOXS로 시작한 경우에도 SOXS 자신의 평가손익을 사용한다. SOXL 변동률을 뒤집어 추정하지 않는다.

반대 매수는 손실 이벤트로 동작하며 새 15분봉이나 새 GBDT 방향 전환을 기다리지 않는다. 최초 본포지션과 이후 재진입 포지션 모두, 홀로 남아 있을 때 자기 매입가 대비 −1.5% 조건으로 빈 반대 종목 진입을 만들 수 있다. 이미 두 종목이 있으면 추가 매수하지 않는다. 이 신규 쉐도우의 반대 진입만을 위한 명시적 전략 규칙으로 구분한다. 본매수의 Neutral/확신도/방패 조건과 실전 진입 로직은 보존한다.

- −1.49%: 반대 진입하지 않음. −1.50% 이하: 최초 조건 충족.
- 유효한 양 종목 가격 감시가 있고 진입 시간대이면 빈 반대 종목의 BUY 의도와 해당 슬롯의 예약 상태를 함께 영속 기록한다. 각 종목 슬롯에 재진입 세대 번호를 부여해 이전 세대의 이벤트로 새 체결을 중복 생성하지 않는다.
- 실전은 신선한 WebSocket Ask와 config 가격 조정으로 주문하고, 증권사 원장의 실제 입고 수량·매입 평균가를 확인한 뒤 포지션으로 저장한다. 주문 접수·로컬 틱만으로 체결 처리하지 않는다. 비교 쉐도우의 가상 매수는 의도 이후의 다음 유효 Ask를 사용한다.
- 매수 체결 전에 최신 본종목 Bid가 −1.5% 위로 회복했다면 의도를 취소한다. 취소가 확정되면 예약을 해제하고 이후 새 유효 조건을 감시한다. 그룹 전체의 반대 진입 기능을 영구 차단하지 않는다.
- 호가가 없으면 `HEDGE_WAITING_FOR_QUOTE`를 기록하고, 최신 양 종목 호가와 손실 조건을 다시 확인한다. 무호가 기간에 가상 체결하지 않는다.
- 매수 대기 한도는 현행 `BUY_TIMEOUT_SEC`와 재시도 횟수 규칙에서 도출한다. 시간대 종료·EOD·운영 종료는 미체결 신규 매수를 취소한다.

두 포지션의 초기 손절은 각자의 체결가 대비 −2%다. 완전 무포지션에서 새 15분봉 신호로 매수한 최초 leg는 +1.5%, 보유 중인 반대 종목의 −1.5% 조건으로 매수한 모든 연쇄 leg는 +1%에서 트레일링을 발동한다. 이후 청산 기준은 **각 포지션의 최고가 × 0.997**이다. 한번 발동하면 수익률이 발동선 아래로 내려와도 해제하지 않는다.

최초 leg가 다른 종목 청산 후 홀로 남더라도 발동선은 +1.5%로 유지한다. 연쇄 leg가 홀로 남더라도 +1%로 유지한다. 같은 종목을 재매수했어도 연쇄 진입이면 +1%다. 두 종목과 미체결이 모두 해소되어 다음 새 15분봉 신호로 시작할 때만 새 최초 leg(+1.5%)가 된다. 예: 매입가 100의 최초 leg는 최고가 101.5에서 발동해 추적선 101.195, 연쇄 leg는 최고가 101에서 발동해 추적선 100.697이다.

최대 TP 10%, 각자의 진입 후 90분 TIME, EOD 전량 청산은 현재 config를 참조한다. 본포지션이 먼저 손절되어도 이미 매수된 반대포지션은 계속 자기 규칙으로 관리한다. 반대포지션이 먼저 청산되어도 본포지션을 임의 청산하지 않는다. 하나가 청산된 후 남은 종목의 최신 손익이 −1.5% 이하이면 빈 종목을 다시 매수할 수 있다. 남은 종목이 이미 손실 조건을 만족하면 새 하향 터치를 기다리지 않고 청산 확정 이후의 유효 호가로 판단한다. 회복한 상태라면 과거 터치 기록만으로 매수하지 않는다.

고점은 유효 WebSocket Bid로 갱신한다. 트레일링 청산 평가 cadence는 현행 config의 POLL 주기를 사용하고, 초기 SL/TP는 MARK에서 감시한다. 각 이벤트에 가격 출처·관측 시각을 보존한다.

## 3. 상태와 예외

그룹은 `FLAT → PRIMARY_PENDING → SINGLE_OPEN ↔ OPPOSITE_PENDING/TWO_OPEN → FLAT`으로 동작한다. `TWO_OPEN`에서 한 종목이 완전히 청산되면 `SINGLE_OPEN`으로 돌아가 남은 종목을 기준으로 반대 진입 감시를 계속한다. 두 종목과 미체결이 모두 없어져야 그룹을 종료하고 새로운 완료 15분봉 신호를 기다린다. 이전 15분봉 신호를 재사용해 즉시 새 그룹을 만들지 않는다.

각 종목 슬롯은 `EMPTY/BUY_PENDING/OPEN/SELL_PENDING`을 별도로 가진다. `OPEN`뿐 아니라 `BUY_PENDING` 및 `SELL_PENDING`도 해당 종목이 점유된 상태다. 매도 체결 확정 후에만 `EMPTY`가 된다. 재진입마다 새로운 leg ID·매입가·고점·진입시각을 부여하고 이전 포지션의 상태를 이어 쓰지 않는다.

| 상황 | 처리 |
|---|---|
| −1.5% 부근에서 반복 진동 | 종목 슬롯 점유·예약 및 현재 세대의 의도 키로 중복 진입 차단 |
| 남은 종목 손실 −1.5% | 반대 슬롯이 완전히 비어 있을 때만 매수. 이미 보유·미체결이면 추가 매수하지 않음 |
| 본포지션 −1.4% → −2.2% 갭 | 본포지션 SL 우선 처리. 전량 청산 뒤 보유·미체결이 모두 없으면 새 15분봉 신호를 기다린다는 최신 사용자 규칙을 따른다. 과거 −1.5% 가격에 반대 종목을 샀다고 가정하지 않음 |
| 위 갭에서 본포지션이 먼저 청산 | 아직 접수되지 않은 연쇄 매수는 발동 보유의 원장 수량을 직전 확인해 차단한다. 이미 접수된 주문은 취소/체결 원장으로 해소하기 전까지 무포지션으로 취급하지 않음 |
| TP/트레일링/EOD로 본포지션 종료 중 반대 매수 대기 | 아직 체결되지 않은 반대 매수 취소. 이미 체결된 반대포지션은 독립 청산 |
| 15:30 이후 −1.5% 터치 | 현행 신규 진입 마감 준수. 반대 신규 매수도 차단하고 기존 보유만 청산 관리 |
| 수량 계산 결과 0 | 미체결/보유로 만들지 않고 이유·잔액·가격·수량 계산값 기록 |
| 피드 지연·누락·순서 역전 | 신규 진입 중지. 실제 관측이 없는 체결은 미해결 상태로 남김 |
| 무시세 TIME/EOD | 독립 CLOCK으로 청산 의도 기록, 다음 유효 Bid에서 체결. 마지막 가격을 현재 체결가로 위조하지 않음 |
| 중복/재전송 이벤트 | 그룹·leg·intent ID와 feed sequence로 중복 체결·수수료 이중 반영 방지 |
| Runner 종료 | 기존 FOLLOW_LIVE_RUNNER에 따라 함께 종료. 종료 자체를 매매 체결로 기록하지 않고 미해결 보유/주문 상태 저장 |
| 재시작 | 복구 원장과 모델/전략 버전 검증 후 감시 재개. 피드가 끊긴 동안의 고점·체결·손절 시점을 추정하지 않으며 해당 구간 평가를 불완전으로 표시 |

## 4. 자금과 성과 계산

그룹 시작 직전 가용 USD를 B로 고정해 본매수 한도 0.49B, 반대매수 예약 한도 0.49B, 현금 여유분 0.02B를 정한다. 이후 한 포지션이 먼저 청산되어 현금이 늘어나도 해당 그룹의 종목별 매수 한도를 확대하지 않는다. 빈 슬롯의 재매수 한도는 최초 0.49B와 실제 증권사 주문 가능 USD에서 최초 2% 여유분을 뺀 금액 중 작은 값으로 제한해 손실 후 부족한 자금을 가상 주입하지 않는다. 두 포지션과 미체결이 모두 해소된 뒤, 다음 그룹 시작 시 새 잔액으로 다시 배분한다.

수량은 각 매수 시점에 `int((B * 0.49) / (현재가 + config.QTY_CALC_BUFFER))`를 기본으로 하되 실제 가용·예약 금액과 예상 체결 비용 범위 안에서만 확정한다. 49%에 다시 98%를 곱하지 않는다. 두 49%를 합친 98%가 총 주문 한도이며 나머지 2%는 비용·가격 여유분이다. 이 49/49 분할은 신규 쉐도우에만 적용되는 사용자 지정 예외이고 실전·기존 트랙의 단일 매수 98% 규칙은 유지한다.

합산 수익률은 `(현금 + 두 포지션의 현재 Bid 평가금액 − 전략 초기자금) / 전략 초기자금`으로 계산하고 실현 비용·미결제 비용 추정치를 함께 반영한다. 본포지션 −1.5% 발동과 각자 −2% 손절은 종목의 매입가 대비 변동률로 판정하며 전체 계좌 손익률과 혼동하지 않는다. 개별 leg 수익률을 단순 합산해 계좌 수익률로 표시하지 않는다.

비교군은 같은 총초기자금을 사용하고, 본매수 49%와 현금 51%를 유지하는 무반대매수 전략을 둔다. 기존 98% 최초 진입 전략은 별도 참고 비교로 표시해 초기 노출 차이를 구분한다. 사용하지 않은 예약 현금도 총자금과 수익률 분모에 포함한다.

비교군은 동일한 최초 진입(+1.5% 트레일링)과 49% 예산을 사용하고, 반대 연쇄 진입의 유무를 비교한다. 연쇄 진입을 포함한 각 leg의 역할과 트레일링 발동선을 기록해, 최초 leg가 중간에 +1%로 바뀌는 구현 오류를 막는다. 기존 98% 예산 트랙은 자금 노출 차이를 명시한 별도 참고군으로 둔다.

원매수 −2% 청산 시 반대 포지션의 +1% 도달은 보장되지 않는다. 반대 진입 이후의 추가 추세, 반등 시 두 leg의 각각의 손실, 비용을 합친 결과로 평가해야 한다.

## 5. 기존 시스템에 연결할 위치

현재 `feed_bridge.features()`는 **추론 전 피처**를 게시한다. 실전의 최종 주문 승인·체결 이벤트를 전달하는 채널은 아니다. 따라서 이 피드를 받았다는 이유만으로 실전 매수와 같은 진입이라고 기록해서는 안 된다.

실제 구현은 `core/live_runner.py:create_live_runner()`가 config의 `OPPOSITE_RELAY_V1`에 따라 `RelayLiveRunner`를 선택하는 구조다. 최초 신호는 기존 MoE/B72 판단을 재사용한다. 최초 수량 hook만 49% 정책으로 분리하고 기존 모델·Neutral·방패 검사는 유지했다.

- `core/relay_live_runner.py`: 종목별 포지션/미체결 scope, 직렬 주문, WebSocket 전용 Bid/Ask, 고점·손절 관측 보존, 보유별 청산과 연쇄 진입, 복구 및 종료.
- `core/relay_policy.py`: config 기반 수량/손절/트레일링/시각 규칙, 계좌·환경 결합 원자적 book과 append-only 이벤트.
- 활성 실행 전략은 `models/active_execution_strategy.json`에 QA 상태와 소스 SHA로 고정한다. 소스/config 불일치이면 신규 진입을 차단한다.
- `models/active_model_manifest.json`과 B72 가중치는 유지한다. B72는 새 전략에서도 최초 방향을 판단하며, 이전 전략 비교용으로 동일 아티팩트를 별도 불변 사본에 보존했다.
- 이전 B72 98% 단일 포지션 전략은 `legacy_b72.py`와 `legacy_strategy.json`으로 기존 consumer에 추가한다. 원래 5개 모델/고정 policy/manifest는 변경하지 않고, 보존 전략의 primary 원장 1개를 더한다. 실제 쉐도우 시작·종료는 기존 FOLLOW_LIVE_RUNNER를 따른다.
- 새 수치와 활성 선택은 config에 선언했고, 기존 쉐도우의 config 검증은 승인된 신규 키·값만 별도로 허용한다.
- 현재 broker 계좌/환경과 READY 증명의 동일성을 신규 실전 BUY 직전에 확인한다. 운영 증명 파일은 임의 갱신하지 않았다.

## 6. 감사 이벤트와 검증 기준

모든 이벤트에 `strategy_id/version`, `run_id`, `group_id`, `leg_id`, 최초/연쇄 역할, leg별 고정 트레일링 발동선, 진입을 발동한 leg ID, 종목 슬롯 세대 번호, `decision_id`, 모델 SHA, 원시 확률/보정 점수, feed sequence, intent/체결/관측 시각, Bid/Ask 출처, 수량, 잔액·예약액, 수수료 가정, 청산 사유를 남긴다.

핵심 이벤트: `PRIMARY_INTENT/FILL`, `OPPOSITE_TRIGGER_SEEN`, `OPPOSITE_WAITING_FOR_QUOTE`, `OPPOSITE_INTENT/FILL/CANCEL`, `TRAIL_ARMED`, `TRAIL_UPDATED`, `EXIT_INTENT/FILL`, `GROUP_CLOSED`, `UNRESOLVED_ON_STOP`. 그룹 종료에는 모든 재진입을 포함한 전체 leg 체결·비용·합산 손익을 연결한다.

구현 완료 조건:

1. −1.49/−1.50/−1.51% 경계, SOXL/SOXS 양방향 대칭, 반복 진동의 같은 종목 중복 진입 차단, 한 종목 청산 이후 같은 그룹의 여러 차례 정상 재진입.
2. 최초 leg +1.5% / 연쇄 leg +1% 발동과 공통 −0.3% 추적. 반대 leg 청산·홀로 남음·동일 종목 재매수 시 역할별 발동선 보존, 완전 무포지션 후 새 최초 진입의 +1.5% 복원. 고점 갱신 및 활성 상태 유지, 초기 SL −2% 보존.
3. 본포지션 먼저 청산/반대 먼저 청산, 반대 SL 후 남은 종목이 조건을 충족하면 빈 슬롯 재매수, 동시 보유 최대 두 종목 및 같은 종목 중복 금지, 모든 보유/미체결 해소 전 새 15분 본진입 금지.
4. 미체결 본매수에서 반대매수 금지, 없는/오래된 반대 Ask에서 체결 금지, 자금 예약·정수 수량·잔액 부족·중복 이벤트 검증.
5. −2% 아래 갭, 의도 생성 후 회복, TIME/EOD/쿨다운, 무시세·지연·재시작·영속 저장 실패 검증.
6. 동일 이벤트의 반복 replay 결과 일치, 그룹별 원장/현금/비용 대사, 총초기자금 기준 합산 수익률 검증.
7. 본/반대 tick 및 호가를 함께 기록한 순차 replay를 주 검증으로 사용. 5분 OHLC만으로 −1.5% 터치와 반대 체결 선후를 정확히 복원할 수 없으므로 그 결과를 실제 tick 전략과 동일하다고 표시하지 않음. OHLC 근사 시 같은 봉의 고가·저가 선후를 가정하지 않고 SL 우선 및 다음 관측 가격 원칙을 적용.
8. 핵심 무결성 `python tests/test_system_integrity.py`, 기존 쉐도우 청산·WebSocket 전용·수명 연결·동일 입력 결과 보존 회귀 통과 후 신규 트랙을 연결한다.

최종 후속 구현: config·실행 코드·쉐도우 연결을 적용한 뒤 재검토 문제도 수정했다. 격리 검증 222개를 통과했고 현재 실전계좌의 실제 원장 대사로 READY 불일치를 해소했다. 실제 운영 Runner 실행·실주문·Telegram 전송은 하지 않았다. 현재 결과는 [후속 수정 기록](RELAY_FIXES_20261020.md)을 따른다.

후속 사용자 변경: 위 초기 설계의 -1.5% 반대 매수 발동선은 **-1.0%로 변경**했다. 추적 하락 -0.3%와 나머지 청산 기준은 유지한다. 관련 검증 총 223개 통과. [최신 발동선 변경 기록](RELAY_TRIGGER_1PCT_20261020.md)을 참조한다.
