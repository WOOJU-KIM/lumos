## 새로 확인한 READY 검증 결함

운영 상태 JSON의 검증 증명은 현재 실전 설정의 계좌 식별값과 다르다. 공백 제거, 숫자 정규화, 계좌 상품코드 결합, SHA256 표현 가능성을 비교해도 일치하지 않았다. 식별값 원문은 기록하지 않았다.

그런데 현재 `_is_valid_reconciliation_proof`는 증명 내부의 계좌값으로 digest를 다시 계산할 뿐, 현재 broker의 계좌 및 환경과 비교하지 않는다. `order_readiness(state)` 역시 현재 broker 식별값을 인자로 받지 않는다. 현재 원본 함수를 AST로 추출해 I/O 없이 실제 상태를 평가한 결과 `ready=True`였다. `KiwoomBroker.send_order`의 BUY 사전 검사와 `_send_tr_request`의 최초 전송 검사 모두 이 결과를 사용한다.

따라서 **현재 계좌와 일치하지 않는 기존 증명이 READY 검사에 수용되는 결함**이 확인됐다. 실제 주문을 전송해 재현하지 않았다. 기존 증명 기준일은 20261014, 증명 sell revision은 0, 현재 revision은 72다. 오래된 날짜·revision 자체를 무조건 결함으로 단정하지 않는다. 이번에 확인한 직접 결함은 현재 실행 계좌·환경과의 비교 부재다.

해당 증명이 생성된 경위나 다른 계좌의 실제 거래 이력이라고 추정하지 않는다. 운영 JSON, READY 플래그, 예약 기록 및 프로덕션 코드는 이번 점검에서 변경하지 않았다. 새 읽기 전용 관측은 운영 검증 증명을 자동 갱신한 것이 아니다.

우선 조치는 현재 broker 계좌·실전/모의 환경에 readiness 검증을 결합하고, 불일치 시 신규 BUY를 차단하도록 수정하는 것이다. 이후 격리 회귀와 진짜 원장 증거 갱신이 필요하다. 단순히 READY 플래그만 바꾸어 해결하지 않는다.
