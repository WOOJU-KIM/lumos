# 연쇄 전략 재검토 후 수정 결과

2026-10-20 사용자 문제 해결 지시에 따라 [재검토에서 발견된 문제](RELAY_REVIEW_20261020.md)를 수정했다. **격리 검증 222개 통과, 현재 실전계좌 원장 대사에 따른 READY 갱신 완료. 운영 Runner와 실주문은 실행하지 않았다.**

## 수정 사항

- **추적 정보 없는 보유의 EOD 청산:** 실제 원장 수량을 다시 조회해 매도한다. 모델 포지션이나 과거 진입 역할·시각을 가짜로 만들지 않고 `RECOVERY` 매도 의도로 기록한다. 원장/미해결 주문 검사는 기존 브로커 헬퍼를 그대로 적용한다. EOD 전에는 이 미추적 보유를 이유로 신규 매수하지 않는다.
- **외부 수량·평균가 변경:** 정상 주문·체결 저널로 설명되지 않는 변경은 `EXTERNALLY_CHANGED_TRACKED_HOLDING`으로 차단하고 기존 진입 기준을 보존한다. 정상 부분체결 및 부분 매도 수량은 원장 증거를 확인한 뒤 갱신한다. 위험 감소를 위한 매도 수량은 최신 실제 보유를 따른다. 연쇄 매수 직전 발동 종목의 평균가도 다시 비교한다.
- **완료 15분봉:** DB의 뉴욕 현지 봉 시작 시각을 기준으로 현재 주기 바로 전 봉을 요구한다. 진행 중인 봉과 미래 봉은 판단용 프레임에서 제외하고, 최신 완료 봉 부재·중복 시각·잘못된 시계열은 신규 진입을 차단한다. 최초 주문/재발주가 다음 판단 주기로 넘어가면 이전 판단으로 제출하지 않는다. 기존 모델·Neutral·config 방패는 유지한다.
- **계좌 결합:** 공통 `order_readiness`에 현재 계좌와 REAL/SIMULATION 기대값 검사를 추가했다. 브로커 BUY 사전 검사와 실제 전송 직전 검사, CircuitBreakerEngine의 거래/재개 검사에서 이를 사용한다. 내부 상태 구조 검증에 쓰이는 무인자 호출은 보존하며 실제 BUY 승인 경로는 broker 식별값을 전달한다. 기존 위험 감소 SELL 원장 검사를 임의 우회하지 않았다.
- **매도 예외 복구:** 원장 조회나 저널 준비 중 실패해도 주문 잠금을 해제한다.

이번 수정에서 `config.py`, 모델 및 쉐도우 아티팩트는 변경하지 않았다. 49%/49%/현금 2%, 최초 +1.5%·연쇄 +1%의 트레일링 발동, 고점 대비 -0.3% 추적, 공통 초기 손절 -2%, TP/TIME/EOD 기준은 유지한다.

## 검증

네트워크와 격리 밖 쓰기를 차단한 소스 복제에서 필수 `python tests/test_system_integrity.py` **9개**, 관련 회귀 **213개**, 합계 **222개**를 통과했다. 재현 사례 외에 오래된 봉이 실제 evaluator의 모델 호출·주문에 도달하지 않는지, 진행 봉 제외·타임존·중복 봉·판단 만료, 다른 계좌/모의 환경 증명의 실전 BUY 차단도 검사했다.

실제 KiwoomBroker 코드를 가짜 HTTP 서버에 연결한 검증에서는 기존 최초 진입→반대 진입→청산→재진입→EOD 시나리오에 더해, 외부 체결 원장에 입증된 5주 보유가 모델 추적 없이도 EOD에 청산되는 것을 확인했다. 첫 테스트에서는 외부 입고만 있고 체결 원장이 없는 fixture를 브로커가 올바르게 차단했다. 실제 외부 BUY 체결 증거를 fixture에 추가해 정상 경로를 검증했으며 브로커 인터락을 완화하지 않았다.

새 계좌 검사에 관련된 `core/circuit_breaker.py`와 `core/kiwoom_broker.py`도 배포 SHA 검증 대상에 추가해 총 7개 소스/config를 고정했다. 최종 manifest와 격리 검증 소스의 SHA가 모두 같고 factory가 RelayLiveRunner를 선택하는 것을 확인했다. factory 검증은 연결·리스너·실주문을 실행하지 않았다.

## 실제 계좌 대사 및 READY 갱신

읽기 전용 인증/조회 API만 허용하는 유지보수 스크립트로 현재 실전계좌의 20261014~20261019 기간 주문 내역 **60행**, 뉴욕 당일 체결 **8행**, 미체결 **0행**, 당일 원장 **0행**, 보유 **0행**을 확인했다. 기간 주문 내역은 연속조회 페이지를 끝까지 수집했다. 원문 응답·인증 토큰은 저장하지 않았다. 요청에 결합된 계좌/환경과 원장 대사는 검증했으며 서버가 계좌번호를 직접 echo했다는 주장은 하지 않는다.

먼저 상태 변경 없는 검증을 통과한 뒤 운영 상태 사본을 보관하고, 기존 `request_sell_migration` → `begin_sell_reconciliation` → `complete_sell_reconciliation` 경로를 사용했다. 완료된 매도 예약은 실제 원장 증거에 따라 정리했다. 저장 가드가 Python 임시파일 생성의 디렉터리 placeholder를 차단한 초기 시도들은 운영 상태 변경 전에 종료됐으며, placeholder와 해당 상태 파일 접두사의 임시파일만 허용한 뒤 정상 완료했다.
