# 매수 전송 직전 WebSocket 주문가 갱신과 미체결 알림

2026-10-20 사용자 지시 반영. 기존에는 WebSocket Ask + 0.03 USD로 가격을 계산한 뒤, 연쇄 wrapper의 원장 확인·브로커 내부 REST 시세 조회·유량 제한·인증·TLS 준비를 거쳤다. 최종 검사는 호가 나이만 확인했고 주문가를 갱신하지 않았다. 10:30 NY에는 102.01/102.18 USD 주문이 모두 0주 미체결로 취소됐고, 당시 관측 호가는 주문가보다 상승해 있었다. 이 기록만으로 가격 지연이 미체결의 유일한 원인이라고 단정하지 않는다.

## 변경

- 연쇄 실전 BUY는 기존 원장 사전 검사 이후 가격 resolver를 브로커에 전달한다. 주문가 계산만을 위한 불필요한 REST 시세 조회는 생략한다. 실제 원장·미체결·계좌 READY 검사는 생략하지 않는다.
- 유량 제한과 인증 처리가 끝난 뒤 요청 본문 준비 시 최신 WS Ask + `config.BUY_SLIPPAGE_ADJUST`로 재계산한다.
- 실제 HTTPS 연결에서는 TLS/프록시 준비를 완료한 뒤 다시 최신 가격으로 본문을 만들어 전송한다. 가격 문자열 길이가 변해도 HTTP Content-Length가 맞도록 갱신한다. 실제 첫 소켓 쓰기 시점의 기존 READY 가드는 유지한다.
- 가격 계산 시 최신 WS 호가 나이, 거래 시간, 완료 봉 만료, 연쇄 진입 조건, 기존 보유 원금과 새 주문 금액의 사이클 배정 한도를 재검증한다. stale·예산 초과이면 HTTP 전송 전에 보류한다. 수량을 임의로 늘리거나 시장가로 전환하지 않는다.
- 실제 주문에 사용한 Ask/Bid·호가 관측 시각·호가 나이·버퍼·지정가를 영속 연쇄 주문 감사 기록에 남긴다. 응답의 실제 지정가는 대기 주문 파일과 주문 로그에도 반영한다.
- 최종 가격 검증에서 거절됐음이 확실한 경우만 제출 대기 플래그를 해제한다. 가격 계산 이후 전송 실패·접수 불명은 기존처럼 미확정 상태를 보존한다. 주문 TR 자동 재시도 금지, 기존 미체결 취소·재발주 횟수는 유지한다.
- 모든 주문의 원장 증거가 CANCELED_ZERO_FILL이고 실제 보유/체결이 0인 경우에만 `BUY_UNFILLED_CANCELLED`로 분류한다. 브리핑은 `ORDER_UNFILLED`와 ‘미체결 취소 완료’, 시도 횟수·체결 0주를 안내한다. 위험 차단이나 체결 여부 불명과 구분한다.

기존 Legacy BUY/SELL 및 조회 요청에는 가격 resolver를 적용하지 않는다. 기존 매도 예약/최초 소켓 가드·미확정 보존 처리를 유지한다. config·모델·READY 파일은 변경하지 않았다. 49%·49%, 버퍼 0.03 USD, 최초+연쇄 1회, 손절/추적/시간/EOD 규칙도 유지한다.
