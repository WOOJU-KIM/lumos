# 실전 연쇄 전략 및 계좌 원장 재검토

검토 시각: 2026-10-20 11:36~11:40 KST. 대상은 현재 선택된 OPPOSITE_RELAY_V1, 기존 주문 헬퍼와 READY 검사, 최초 15분 판단, 복구·청산, 보존 쉐도우 연결과 아티팩트다. 운영 코드/config/READY는 변경하지 않았다. 실전 Runner, 실제 주문·취소, Telegram을 실행하지 않았다.

## 현재 계좌 관측

현재 설정된 실전 인증정보로 인증 1회와 읽기 전용 원장 조회 6회를 실행했다. 잔고 0행, 당일 및 예약일 미체결 0행, 체결 8행, 기간 주문내역 8행, 당일 원장 0행이다. 각 조회는 연속조회 종료를 확인했다. 체결·주문 행 수는 왕복 거래 횟수가 아니다. 로컬에 남은 SOXL 5주 ACCEPTED 매도는 공통 3-원장 reducer에서 FILLED, 체결 5주·잔여 0주로 확인됐다.

따라서 현재 잔고가 어긋났거나 해당 매도가 미체결이라고 볼 증거는 없다. 응답이 계좌 식별값을 직접 되돌려 주지는 않아 서버의 계좌 echo 검증과 설정 인증정보 기준의 조회를 구분한다. 토큰·계좌번호·주문번호·원문 응답을 출력/저장하지 않았다.

## 확인된 문제

1. **P1 — 추적 정보 없는 실제 보유를 EOD에 청산하지 못함.** `core/relay_live_runner.py:372`, `:488`. 새 전략의 종목별 포지션 정보가 없으면 일반 위험 관리와 SELL 헬퍼 모두 반환한다. 기존 전략의 보유를 가진 상태에서 전환하거나 포지션 파일이 사라진 뒤 재시작하면 실제 원장 보유가 있어도 처리하지 못한다. 격리 재현: SOXL 실제 보유를 모사한 5주, 15:56 NY, 원장 대사 및 EOD SELL 호출 후 제출 0건·5주 유지. 신규 진입 차단만으로 EOD 현금화는 보장되지 않는다. 실제 잔고 기준의 복구/전환 또는 명시적인 비추적 잔고 청산 경로가 필요하다.

2. **P1 — 이미 추적하는 종목의 외부 수량·평균가 변경을 정상 보유로 덮어씀.** `core/relay_live_runner.py:458`. 미해결 주문이 없는 기존 포지션도 원장 값으로 바로 갱신하며, 변경 원인이 저널에 있는지 확인하지 않는다. 격리 재현: 최초 48주를 만든 뒤 외부 보유를 51주·다른 평균가로 변경하자 로컬도 51주로 저장됐고 mismatch=None, 반대 종목의 사전 진입 검사는 True였다. 이 경우 기존 leg의 손절·트레일링 기준까지 변한다. 기존 수량/평균가와 원장 차이를 정상 체결 증거로 설명할 수 있을 때만 갱신해야 한다. 종전 전환 문서의 외부 거래 차단 설명은 이 사례까지 보장하지 않는다.

3. **P1 — 실제 새 완료 15분봉과 판단 주기의 일치를 확인하지 않음.** `core/relay_live_runner.py:319`, `core/live_runner.py:2602`. relay의 decision key는 벽시계로 생성되며, 실제 마지막 완료 봉의 식별값에 결합되지 않는다. 기본 snapshot 검사는 평일 봉에 최대 48시간 등 넓은 age를 허용하고 장중 동기화 결과도 새 봉 입고 증거로 검사하지 않는다. 격리 재현: 10:00 NY에 마지막 봉 09:00, 현재 호가는 신선한 상황에서 snapshot data_stale=False, relay 최초 진입 수량 48주. 이 재현은 snapshot/수량 게이트 확인이며 실제 주문 전송은 없다. 공급 지연이나 동기화 실패 시 같은 오래된 봉을 다음 판단 주기에 다시 사용할 수 있다. 봉 시작/종료 시각 규약에 맞춘 완료 봉·현재 주기·중복 판단 검증이 필요하다.

4. **기존 READY 검사의 현재 계좌 결합 누락이 여전히 존재함.** `core/circuit_breaker.py:109`, `core/relay_live_runner.py:170`. 현재 운영 증명의 기준일은 20261014이며 verified_account는 현재 실전 설정과 다르다. 순수 AST로 원본 readiness 함수를 실제 상태에 평가하면 ready=True다. 새 relay의 추가 계좌 검사는 이를 거부하므로 현재 신규 실전 BUY는 차단된다. 현재 잔고 불일치와 다른 문제다. 공통 브로커 검사도 현재 계좌/환경에 결합한 뒤, 실제 원장 대사를 통해 증명을 갱신해야 한다. 이번 읽기 전용 관측을 이유로 READY 플래그나 증명을 임의 갱신하지 않았다.
